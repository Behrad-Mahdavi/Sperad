# اسپراد | Sperad

> پلتفرم تصمیم‌گیری شخصی‌سازی‌شده برای تمرین بدنسازی بر پایه‌ی مدل‌سازی وضعیت پنهان بدن (Banister Impulse-Response)، فیلتر کالمن بیزی، و بهینه‌سازی ترکیبی با MILP.

---

## معماری کلی و ساختار مونو‌ریپو

پروژه به صورت مونو‌ریپو با **Turborepo** و **pnpm workspaces** سازمان‌دهی شده است:

```
sperad/
├── apps/
│   └── web/                 # کلاینت PWA بر پایه‌ی Next.js 15 (App Router)، Dexie و تایپوگرافی IRANSansX
├── packages/
│   ├── shared/              # اسکیماهای Zod و تایپ‌های اعتبارسنجی مشترک داده
│   ├── engine/              # پکیج توابع خالص TypeScript (فرمول‌های Banister، Epley/Brzycki و کالمن)
│   ├── database/            # تایپ‌های تولیدشده از مدل داده و کلاینت تایپ‌سیف Supabase
│   └── sim/                 # شبیه‌ساز کاربر مصنوعی و تست‌های ویژگی‌محور (Property-based)
├── supabase/
│   ├── migrations/          # مایگریشن‌های پایگاه‌داده Postgres با سیاست‌های امنیتی RLS
│   └── seed.sql             # سید ۱۴ گروه عضلانی و ۳۶ حرکت اصلی بدنسازی با بردار خستگی و ضرایب SFR
├── docs/
│   └── technical-brief.md   # سند بریف فنی کامل و فرمولاسیون الگوریتم‌ها
└── workers/
    └── stats/               # ورکر پایتونی رگرسیون بیزی و برازش پارامترها (فعال در فاز ۳)
```

---

## اصول طراحی سیستم

1. **داده‌ی تمیز و کم‌زحمت:** ورودی هر ست با حداقل تپ و زیر ۵ ثانیه ثبت می‌شود.
2. **معماری آفلاین‌محور با Outbox:** حتی هنگام قطعی کامل آنتن باشگاه، داده در دیتابیس محلی (Dexie IndexedDB) ذخیره و به محض اتصال به صورت ایدمپوتنت با `client_uuid` همگام می‌شود.
3. **Priors پژوهش‌محور:** شروع از پیش‌فرض‌های مطمئن و شخصی‌سازی تدریجی با یادگیری بیزی.
4. **ایمنی بر بهینه‌سازی:** رعایت محدودیت‌های سقف بار، جهش وزنه و مود Re-entry بعد از وقفه تمرینی.
5. **توضیح‌پذیری:** هر پیشنهاد دارای یک دلیل مستند (`rationale`) در لاگ تصمیم‌ها است.

## دستورات اجرایی

### نصب وابستگی‌ها:
```bash
pnpm install
```

### اجرای محیط توسعه:
```bash
pnpm dev
```

### اعتبارسنجی تایپ‌ها (Typecheck):
```bash
pnpm check-types
```
